# 阶段 0：项目现状只读审计

读取总控提示词。当前阶段只审计，不实现、不重构、不升级依赖、不删除文件、不格式化全仓库。

## 工作
1. 检查 Git 分支、工作区状态、提交历史、忽略规则和仓库目录。
2. 识别 Godot 版本、项目入口、主场景、自动加载、输入映射、导出配置和插件。
3. 追踪球桌、球体、球杆、摄像机、UI、游戏状态、物理、规则、AI、网络、存储的现有实现与调用链。
4. 检查资源格式、资源规模、缺失引用、导入状态和许可证。
5. 检查 Android 导出链、目标/最低 API、权限、生命周期、SDK/JDK/Gradle 约束。
6. 检查测试、CI、构建脚本、性能基准和现有缺陷。
7. 将目标需求逐项映射为：已实现、部分实现、未实现、无法确认。

## 证据要求
每项重要结论给出文件路径、类/节点/函数或命令输出。不能只根据文件名推断功能。无法运行的检查写明原因。

## 输出
在 `docs/audit/` 创建：
- `repository-inventory.md`：目录、入口、模块和资源清单。
- `gameplay-status.md`：玩法与需求差距。
- `physics-audit.md`：物理模型、参数、碰撞与测试现状。
- `architecture-audit.md`：依赖、模块边界、耦合与风险。
- `android-audit.md`：Android 导出、权限、生命周期和兼容性。
- `assets-dependencies.md`：资源来源、许可证、插件和依赖。
- `test-build-audit.md`：测试、CI、构建与复现情况。
- `risk-register.md`：风险、严重度、证据、缓解建议。
- `audit-summary.md`：总体结论、阶段门禁建议。

## 验收门禁
审计覆盖所有核心领域；每个需求有状态；高风险问题有证据和建议；没有改动运行时代码或资源。结束后列出新增文档和 Git diff，等待维护者明确批准阶段 1。
