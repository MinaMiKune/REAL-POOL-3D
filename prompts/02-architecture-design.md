# 阶段 1：架构设计与技术验证

前置条件：阶段 0 审计已由维护者批准。先复核审计结论和当前代码；若仓库状态变化，先更新相关发现。

## 设计任务
1. 定义模块边界、依赖方向、场景树和数据流，尽量复用合理的现有实现。
2. 设计物理核心：坐标与单位、固定步长、球状态、碰撞求解、摩擦/旋转、袋口和静止判定。
3. 设计美式 8 球规则状态机：开球、球组判定、击球合法性、犯规、手中球、8 号球胜负。
4. 设计五档 AI 的能力参数、候选球评估、走位规划和非作弊失误模型。
5. 设计 LAN：发现、房间、协议版本、主机权威、同步、重连、超时和安全校验。
6. 设计 SQLite 数据模型、迁移、事务、备份/损坏恢复策略。
7. 设计横竖屏 UI、输入抽象、镜头控制、设备安全区和分辨率适配。
8. 制定 Android API 37 导出和权限方案，核验工具链与插件支持。
9. 定义性能预算、测试策略、日志与崩溃诊断方案。

## 技术验证
对高风险选型做最小 PoC，优先验证 Android 导出、SQLite 插件、网络 API、渲染器和物理测试可行性。记录真实版本、命令、结果和限制。未经实测的结论标记待验证。

## 输出
在 `docs/architecture/` 写架构总览、模块接口、数据模型、网络协议草案、物理模型、Android 技术方案、性能预算和 ADR（架构决策记录）。更新路线图与需求追踪表。

## 门禁
架构能映射到现有仓库；重大依赖有许可证与兼容性证据；风险有降级方案；没有提前实现后续阶段功能。等待维护者批准阶段 2。
