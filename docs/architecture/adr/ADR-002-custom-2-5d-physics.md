# ADR-002：定制固定步长 2.5D 权威物理

- 日期：2026-11-11
- 状态：Accepted；正式实现属于阶段 3/4，当前未实现

## 背景

需求要求可信、可控、可复现的定制 2.5D 物理，不接受直接以通用刚体作为最终方案。需要同时表现三维旋转、稳定碰撞、库边、袋口与可测试规则事件。

## 决策

使用米/秒/弧度的平面球心运动和三维角速度，`240 Hz` 初始固定 tick、扫掠圆 TOI、稳定接触排序、有限冲量迭代、独立滑动/滚动摩擦、带 jaw 的库边和显式袋口捕获。Godot RigidBody3D 只做非权威表现/查询，不决定比赛。物理配置版本化，静止/不收敛严格区分。

## 备选方案

1. **Godot RigidBody3D 全 3D**：开发快且有接触，但跨版本参数/顺序控制弱，跳球等自由度超出 2.5D 目标，拒绝作为权威。
2. **Godot RigidBody2D**：平面方便，但三维角速度、杆法和台面接触模型需大量绕开，拒绝。
3. **离散定点 2D 自研**：简单，但高速穿透和稳定事件顺序风险大，拒绝。
4. **成熟外部刚体库**：仍需 GDExtension/确定性与 Android 适配，且通用模型不等于台球模型，暂不引入。
5. **定点数/严格锁步**：可增强跨端一致性，但实现/调试成本高；LAN 主机权威无需客户端锁步，暂不采用，保留未来研究。

## 理由

平面自由度足够回合制 8 球，三维角速度可支撑跟/缩/塞和视觉旋转；CCD 与固定事件顺序更适合规则测试、AI rollout、快照和主机权威。分层使渲染帧率和设备性能不改变权威步长。

## 代价

- 需要自行处理多接触、初始重叠、jaw、睡眠、数值误差与校准，工作量显著高于刚体节点。
- 240 Hz 和多 rollout 有移动 CPU 压力，需 benchmark/对象复用/worker。
- 不模拟跳球、真实杆接触、空气滚动和台呢织向，视觉“高仿真”不能等同完整物理仿真。

## 风险与降级

多球接触可能不收敛，跨平台可能分歧，参数可能缺乏真实感。设置事件/tick 上限、NaN 检查、技术错误和诊断快照；不以强制静止或通用刚体替代掩盖。若性能不足，先减少 AI rollout/表现开销，不能降低权威频率或改变比赛结果。

## 验证方法

- 本阶段隔离 Python 探针验证正碰 TOI、弹性正碰动量/能量、库边反射、高速防穿透、减速不过零和滑动到滚动公式特例。
- 阶段 3/4 在 Godot 实现同一数值矩阵，并增加斜碰、多球、旋转冲量、六袋 jaw、极值、快照和 30/60/120 Hz 渲染独立性。
- 在 Windows/Android 记录同 fixture hash/容差与误差，不预承诺位级一致。
- 用真实球桌/录像/测量建立参数校准记录；无证据前标待校准。
