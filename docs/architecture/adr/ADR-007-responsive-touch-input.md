# ADR-007：统一输入命令、手势状态机与响应式横竖屏

- 日期：2026-11-11
- 状态：Accepted；真实设备验证 `BLOCKED`

## 背景

需要横竖屏、完整触控、镜头和安全区适配；Android 17 大屏不能依赖方向锁定。瞄准、力度、杆点和多指镜头若共享坐标/状态容易误击。

## 决策

输入分为短暂预览和唯一规范 Shot/Placement 命令。`InputRouter` 使用 pointer ID 和显式状态机管理单指瞄准、双指缩放、镜头 orbit、力度和确认；UI 先消费，桌面只处理 unhandled input。布局由可用矩形/safe area 驱动，横竖屏采用不同 Control 容器排布；方向变化取消手势并重算映射。

## 备选方案

1. **锁定横屏**：实现简单但违背横竖屏及 Android 17 大屏要求，拒绝。
2. **同一缩放 UI 自动拉伸**：少工作但触控目标、信息密度和 3D 比例差，拒绝。
3. **原生 Android UI/Kotlin**：平台控件强但双 UI 栈和 Godot 交互复杂，未证明必要，拒绝。
4. **每控件直接写球/规则**：快速原型但状态重复且无法 LAN/回放，拒绝。
5. **松手立即击球**：操作短但误触风险高，采用明确确认。

## 理由

Godot Control/Input 已提供跨平台基础，自研状态机只处理项目手势语义。统一命令使人类、AI 和 LAN 走同一验证/回放路径。响应式布局同时覆盖手机、分屏和 sw≥600dp，避免假设方向。

## 代价

- 需要处理 pointer cancel、系统手势、文字缩放、窗口变化和多指冲突的大量设备测试。
- 横竖屏两套布局增加 UI 维护，需共享组件而不是复制业务状态。
- 明确确认多一步操作，需要可用性测试验证流程。

## 风险与降级

复杂手势不可用时提供按钮模式、镜头预设和力度滑条等等价控件；布局不满足时隐藏非关键效果而不是遮挡击球。任何坐标不确定/方向变化都取消预览，不自动提交旧命令。

## 验证方法

单元测试手势迁移和坐标转换；真实设备覆盖单/多指、pointer cancel、系统返回边缘、旋转/分屏/折叠、safe area、字体缩放和误触。LAN 下确认同一命令在主机规范化，回放只保存最终命令。
