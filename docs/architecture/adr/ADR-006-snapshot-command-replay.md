# ADR-006：快照、命令、事件和版本化回放

- 日期：2026-11-11
- 状态：Accepted；实现属于阶段 8，跨版本重算不作默认承诺

## 背景

物理、规则、AI、引擎升级可能改变重算结果。只记录视频不适合规则核查，只记录 seed/输入又无法保证长期或跨平台一致。需要兼顾可复现诊断、可播放和存储成本。

## 决策

回放格式 `pool-replay-1` 保存初始 Match/Ball 快照、规范化 Shot/Placement/Choice 命令、AI/首局 seed 与算法版本、物理事件、RuleDecision、每 shot 最终状态和 hash，以及完整 VersionSet/config hash。SQLite 将索引与二进制 chunk 分离。播放优先明确支持的重算；不一致或不支持时回退到已记录快照，最低只显示元数据。

## 备选方案

1. **只录视频**：播放稳定但占空间、无法查询命令/规则或复算，拒绝作为唯一回放。
2. **只存 seed 和输入**：最小但强依赖引擎/平台/调用顺序，无法保证长期正确，拒绝。
3. **每 tick 全量球态**：播放简单但数据量和 I/O 大，首版不采用；可按需关键帧优化。
4. **每 shot 全状态+命令+事件**：本决策，平衡诊断和存储。
5. **强制旧版本重算**：需要保留多引擎/参数链，复杂且易误导，只有明确兼容矩阵才启用。

## 理由

命令提供最小可复现输入，事件/决策支持解释和音画，shot 最终快照提供不依赖浮点重算的播放锚点。版本/hash 让分歧可见，而不是静默播放另一个结果。索引/chunk 分离避免列表读取大 BLOB。

## 代价

- 每 shot 保存状态和事件增加存储、规范编码和迁移工作。
- 快照播放不能证明当前物理重算一致；UI 必须区分播放模式。
- 跨版本兼容需要真实矩阵，不能自动“尽量播放”。

## 风险与降级

hash 分歧立即停止重算并报告；若快照完整可切换快照路径，否则只显示元数据。恶意/损坏导入限长并拒绝，不执行 Variant/Object。物理 major 改变时保留旧格式查看，不强行迁移结果。

## 验证方法

测试规范二进制 round-trip、尾随/截断/超大长度、版本拒绝、逐 shot hash、快照恢复和 seek。相同 fixture 在实际 Windows/Android 版本组合比较；注入一个事件/状态差异必须可检测。旧版本只走声明支持的路径，数据库故障不影响最近完整边界。
