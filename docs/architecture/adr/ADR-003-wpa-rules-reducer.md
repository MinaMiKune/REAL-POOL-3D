# ADR-003：WPA 2026 数字变体与纯规则 Reducer

- 日期：2026-11-11
- 状态：Accepted；数字差异待维护者审查，规则实现未开始

## 背景

“美式 8 球”存在多种变体。若不固定文本和优先级，开球分组、8 号球、三次犯规等很容易混入不兼容规则。物理事件和 UI 也不应各自裁决。

## 决策

默认 `WPA_2026_DIGITAL_V1`，依据 WPA 2026-10-21 通用规则和第 4 节 8-Ball。使用纯 `RulesReducer` 从击球前 MatchState、规范命令和有序 ShotResult 生成新状态/RuleDecision。开球不自动分组；普通击球叫球叫袋或 safety；非法开球提供 WPA 选择；8 号球严重结果优先。默认不使用三次连续犯规判负。

数字化差异显式化：不伪造现实裁判检测，不支持跳球/真实杆接触，首局用记录的 seed 抽签替代 lag，后续 rack 轮换开球；袋口悬球等未建模事项不宣称完整覆盖。

## 备选方案

1. **酒吧/常见简化规则**：用户熟悉但来源不统一，易出现开球即分组、8 直接重摆等差异，拒绝作为默认。
2. **BCA/APA 等其他规则**：可作为未来版本，但需要另一套状态与测试，不能混用。
3. **可配置所有规则开关**：组合爆炸且语义冲突，首版只支持经过测试的完整变体。
4. **UI/物理各自判断**：会产生重复状态和联机分歧，拒绝。
5. **完整现实裁判模拟**：需要外部观察和跳球等模型，超出 2.5D 能力，不伪造。

## 理由

WPA 文本权威、条款清晰，2026 版本明确 8 球不包含三次连续犯规判负。纯 reducer 可脱离 Godot 场景和 LAN 独立测试，人与 AI/客户端共享验证，回放可重建裁决依据。

## 代价

- 开球选择、8 特殊分支、同时首碰和手中球增加状态/fixture 数量。
- 数字抽签和未模拟裁判事项意味着不能标为完整 WPA 竞赛认证。
- 新变体需要新 rules major、房间协商和回放兼容矩阵。

## 风险与降级

维护者可能不接受数字首局规则或事件歧义处理；在实现前审查 ADR，必要时只改明确版本和文档。技术错误不得转为犯规/胜负；未知变体拒绝加入而不是按默认规则继续。

## 验证方法

按规则文档 RULE-B/G/E/C/X 测试开球 3/4 球碰库、开球 8、开放桌、叫袋、safety、8 胜负、手中球、重复命令、非静止和 reducer 纯度。属性测试检查组互补、终局唯一和相同输入深层相等。典型争议由人工按 WPA 条款复核。
