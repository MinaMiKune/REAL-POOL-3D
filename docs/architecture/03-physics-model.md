# 定制 2.5D 台球物理模型

## 1. 目标与非目标

目标是在平面桌面上模拟可复现的球心运动、三维角速度、球-球/库边碰撞与落袋，并以三维球体表现旋转。2.5D 不模拟跳球、球杆真实接触、球体空中翻滚、台呢织向或复杂形变；这些不得宣称高仿真已覆盖。Godot `RigidBody3D` 不参与权威结果。

所有系数初值都是**待校准估计**，不是实测台球参数。阶段 3 必须用数值场景和真实球桌/设备对照记录误差。

## 2. 坐标、单位与状态

- 米、秒、千克、弧度；桌面中心为原点，`+x` 向右，`+y` 指向 Foot Rail。
- 映射到 Godot：`Vector3(x, cloth_height, y)`，Godot `+Y` 为高度；不直接把权威 `Vector2` 与渲染坐标混用。
- 角速度 `(ω_x, ω_y, ω_z)` 采用映射后的右手世界轴，单位 rad/s；`ω_y` 是竖直轴旋转。权威平面的 `(x,y)` 仅用于球心平动，不能与 Godot 局部高度轴混用。
- 初始 9 英尺台面估计：2.54 m × 1.27 m；球半径 `r=0.028575 m`，质量 `m=0.17 kg`，转动惯量 `I=2mr²/5`。
- `BallState` 分离平动模式 `{SLIDING, ROLLING, STATIONARY}`、处置 `{ON_TABLE, POCKETED, OFF_TABLE}`、三维角速度与睡眠计数，避免“停滚但仍在旋转”无法表达。
- 视觉四元数由三维角速度积分；它不是碰撞检测的额外自由度。

权威核心优先使用 GDScript `float` 标量及自定义二元/三元数学结构，不在未核实精度前假定 `Vector2/Vector3` 的 `real_t` 精度。阶段 2 的精度 PoC 必须记录实际引擎和 ABI 行为。

## 3. 固定步进与确定性边界

建议 `tick_hz=240`、`dt=1/240 s`，渲染通常 60 Hz。`_physics_process(delta)` 只向 accumulator 添加时间；每个固定 tick 按顺序执行，球视图在前后快照间插值。

1. 读取仅在 tick 边界排队的命令。
2. 保存上一渲染快照。
3. 计算本 tick 最早碰撞并推进到该时刻。
4. 以稳定顺序求解接触、更新旋转和摩擦。
5. 处理剩余时间；达到事件上限则报告不收敛。
6. 发出有序事件，更新睡眠计数与校验。

实时比赛由 `MatchController` 按每帧预算调用 `step_one_tick()`，每渲染帧最多执行 16 tick，超出工作留到后续帧，不丢弃权威 tick。`run_until_rest()` 只用于 headless 测试或 AI worker；worker 必须有 tick/时间预算和取消通道，不得在渲染主线程一次性跑完整 shot。后台恢复不补算离开期间的 wall-clock 时间；回合制游戏在暂停点继续。相同命令流在同一引擎版本、配置和平台上应复现；跨 CPU/引擎版本的位级一致**不作承诺**，以容差、哈希诊断和主机权威降低风险。

## 4. 碰撞检测与求解

### 4.1 连续检测

每 tick 使用保守推进/扫掠圆求最早接触，防止高速穿透：

- 球-球：相对位置 `p`、相对速度 `v`，解 `|p+vt|=2r` 的最小 `t∈[0,remaining]`。
- 库边：球心扫掠圆对库边线段及端点的扩张形状求 TOI；袋口处库边必须断开，不能用四条无限长墙代替。
- 同时接触：先按容差聚合，再按 `(TOI, contact_type_priority, min_ball_id, max_ball_id, cushion_id)` 稳定排序。
- 每个接触批次进行有限次冲量迭代和微量位置修正；只修正穿透，不注入可见速度。

初始建议每 tick 最多 8 个接触批次、4 次迭代；全局 shot tick 上限 60 秒模拟时间。达到上限是技术失败，需保存诊断，不得强行“静止”。参数由阶段 3 压测调整。

### 4.2 球-球冲量

法线 `n=(p_b-p_a)/|p_b-p_a|`，相对法向速度 `v_n=(v_b-v_a)·n`。仅在 `v_n<0` 时求：

```text
j_n = -(1 + e_ball) v_n / (1/m_a + 1/m_b)
```

将 `j_n n` 施加到两球。切向冲量考虑接触点滑移与转动，受球-球摩擦约束 `|j_t| ≤ μ_ball j_n`，用于表现塞球造成的切向偏移/旋转交换。完全弹性、无摩擦正碰是守恒测试特例；正式参数不使用 `e=1`。

初始重叠先求稳定分离与零时刻接触，避免重复释放能量；同一对球在分离前不得重复施加同向弹性冲量。高速、多球和贴库同时接触均需要专项测试。

### 4.3 库边反弹与旋转

库边由有袋口缺口的线段/圆弧和 jaw 参数组成。接触冲量改变法向速度，切向摩擦与球面滑移共同决定“跟/缩/塞”的响应：

- 法向恢复系数 `e_cushion` 与切向摩擦 `μ_cushion` 分参数，不使用统一反射系数。
- 接触点相对速度包含 `ω × r_contact`；切向有效质量包含 `I`，避免只反转线速度而旋转不变。
- 法向穿透用位置修正；角速度冲量由 `r_contact × J / I` 更新。
- 袋唇/角袋 jaw 使用局部几何，不将边角反射为任意“吸袋方向”。

## 5. 摩擦、滑动与旋转

球与台呢接触点为 `-r n_up`。接触滑移：

```text
u = v + ω × (-r n_up)
```

当 `|u| > slip_epsilon` 时处于滑动，滑动摩擦力方向为 `-u/|u|`，大小以 `μ_slide m g` 为初始模型；力矩同时更新三维角速度。滑动到滚动的无初始旋转特例用于探针：

```text
t_roll = 2 v0 / (7 μ_slide g)
v_roll = 5 v0 / 7
```

当滑移低于阈值进入滚动，使用滚动阻力 `μ_roll m g` 和独立旋转衰减。每 tick 减速采用不会过零的限量更新：

```text
speed_new = max(0, speed - deceleration * dt)
```

不能用简单线性插值导致低速振荡。竖直轴旋转 `ω_y` 在停滚后仍可衰减；只有平动、接触滑移与旋转都满足阈值才进入静止。

## 6. 击球输入映射

`aim_angle` 决定平面方向，`power∈[0,1]` 经版本化曲线映射到冲量/初速度；`cue_offset_x/y` 是归一化杆点，向量长度限制在可用半径内。输入先规范化再进入物理，因此回放只存最终命令。

- 高/低杆产生前/后旋转，左右塞产生竖直轴旋转。
- 杆法强度、最大初速度、miscue 阈值是配置项，不硬编码在 UI。
- 不模拟真实球杆双次接触、推杆或跳球；规则层禁止不支持的输入而不是假装裁判已识别。

## 7. 球袋与出界

球袋模型由入口平面、两侧 jaw、捕获区域和袋内表现路径组成：

1. 扫掠轨迹与袋口/jaw 先求接触，擦边可弹回。
2. 球心按配置方向越过捕获平面且位于入口宽度内，或进入明确捕获区域，才生成一次 `BALL_POCKETED`。
3. 不使用远距离径向“吸力”；捕获区域不得覆盖正常库边线段。
4. 入袋后立即退出平面碰撞，由表现层按事件播放下沉；规则使用事件中的 `pocket_id`，不是动画结束回调。
5. 越过非袋口外边界则 `BALL_OFF_TABLE`，与落袋严格区分。

数值模型与 WPA“静止在袋内”的语义差异需在阶段 3 袋口测试后记录；不得以视觉接近袋口直接判落袋。

## 8. 静止与不收敛

建议初始阈值（全部待校准）：线速度 `<0.003 m/s`、接触滑移 `<0.005 m/s`、角速度各分量低于对应阈值，连续至少 `0.25 s`。随后将微小速度显式归零并发 `SHOT_AT_REST`。

`run_until_rest()` 只在全部在台球满足条件、没有待处理接触且事件队列为空时结束。超时、NaN/Inf、越界状态、事件上限均为 `NON_CONVERGENCE`；保存配置、seed、输入、tick、状态和最近事件，主比赛进入技术错误页。

## 9. 测试与校准矩阵

| 类别 | 数值断言 | 场景/设备验证 |
|---|---|---|
| 正碰/斜碰 | 动量、弹性特例能量、首碰 ID | 慢放轨迹和接触点 |
| 连续/多球 | 稳定事件顺序、无异常增能 | 开球与三角接触 |
| 库边 | 法向恢复、切向滑移、无穿透 | 不同角度/杆法 |
| 旋转摩擦 | 滑动到滚动、减速不过零、停转 | 跟杆、缩杆、侧塞 |
| 袋口 | 捕获一次、擦边、无远吸、出界区分 | 六袋和 jaw 边角 |
| 极值 | 高速 TOI、低速收敛、初始重叠 | 长局与最大力度 |
| 复现 | 30/60/120 Hz 渲染等价、快照恢复 | Windows 与 Android 分别记录 |
| 故障 | NaN/事件上限显式报错 | 日志包和恢复流程 |

物理参数版本格式 `pool-physics-major.minor`；影响结果的变更提升 major，并触发回放兼容策略。阶段 3 完成前不得使用“真实”“无穿透”“跨平台确定”作为已验证结论。
