# 风险登记册

## 1. 严重度口径

- **Blocker**：阻止项目导入、构建、运行或核心验证。
- **Critical**：核心产品要求整体缺失，若不解决将使核心验收不成立。
- **High**：关键架构、平台或质量风险，需要在对应实现前或早期验证。
- **Medium**：工程治理、复现或发布风险，当前不阻断文档审计但会持续放大。
- **Low**：局部、短期或易恢复问题。

本登记册记录“当前缺口的风险”，不把空仓库中的每个缺口都伪装成已发生运行时缺陷。共同基线：`bf0cbba70867f09ad7363e455dd7bcdc89a5092e`，15 个跟踪文件全部为 Markdown。

## 3. 风险优先顺序

1. **先解除可验证性阻塞**：R-01、R-02。没有项目和工具链时，任何运行结论都不可信。
2. **再处理核心正确性与架构**：R-03、R-04、R-07、R-08、R-12。
3. **同步建立质量与平台证据**：R-05、R-06、R-09。
4. **持续治理**：R-10、R-11、R-13。

严重度反映当前对交付的阻断程度，不代表后续应跳过阶段门禁。任何风险缓解工作都需在维护者批准对应阶段后执行。
